### Added

- AiSearchAgent (#2223, AiSearchAgent slice): a new PortThink agent (`AI_SEARCH_AGENT` DO, migration v12) giving the fleet one agent door onto the same Cloudflare AI Search instance the SearchHub knowledge surface serves. It reaches the instance three ways in the user-set priority order — the `ai_search_namespaces` binding as the agent tool (primary; powers both the turn tool and the direct `search()` method), the instance's public MCP `search` tool via the repo's RemoteMcpClient (second), and the standalone REST API via `ETradeAISearchService` reused as-is (last resort) — with hub-consistent S2 result fields and bucket-key provenance from the shared chunk mapping, every answer labelled with its serving path. Degradation is honest: no configured path is a typed degraded result, a failing path falls through with the failure recorded, and the REST leg's fallback-labelled (`semantic_cache`) rows are surfaced as degraded and withheld, never served as live results. The A2A door serves exactly `aisearch.search` (new card + A2A-owned resolution entry). The namespace binding itself ships config-gated: its dashboard-issued namespace id is not in the repo, so the `ai_search_namespaces` wrangler entry is the owner's enablement step, named in `src/types.ts`. No provisioning or upload (the #1169 S4-5 bridge stays dashboard-gated), and the SearchHub routes are unchanged — serving the hub through the agent belongs to the #1169 probe-gate sequence.
