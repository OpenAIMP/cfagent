### Changed
- Agent Mesh S9 (#2375, programme #2225 G4): a chat trade now runs as a TradingTradeWorkflow through TradingAgent's approval door. Three new turn commands ride the mesh door (`src/agents/orchestrator/meshDoors.ts`): `start_trade_approval` (mcp:trade) submits an existing proposal (from `propose_stock_trade` / `propose_options_trade`) to the agent's approval door, starting the durable approval run; `decide_trade_approval` (mcp:trade) delivers the human's decision — the authorizer DID is derived server-side from the turn's acting identity and is never a tool argument; `get_trade_approval_status` (mcp:read) reads the run from the TRADE_WORKFLOW binding's own status surface (Trading writes no D1 projection, and no second tracker is added). The workflow's settle step now delegates to the order owner's TradingAgent approval door (`executeApprovedOrder`), so settlement runs inside the Durable Object that holds the draft store, through the same settle core and the same platform order code as before — no live-order behavior changes: amounts, limits, risk checks, approval policy, and the execution service are untouched, and the legacy `etrade_preview_order` / `etrade_execute_order` path is unchanged. Enabling fix: `settleTradingOrder` accepts the caller's draft-store ORM and `executeApprovedOrder` threads the instance ORM into platform resolution — previously the settle resolved its platform ORM-less, so no real door-path draft could ever be found. The S6 approval-door boundary is re-scoped, not removed: the synchronous settle is still never typed on the door nor door-called; the workflow's settle step is its only caller. Conformance: TradingAgent's `sessions` cell stays GAP, explicitly re-dispositioned to the programme backlog (S9 made chat the first production caller of the agent's door surface, but that path is typed RPC and drives no turn on the class, so no transcript accumulates); the `connections` and `routing` evidence now records the approval-door caller.
