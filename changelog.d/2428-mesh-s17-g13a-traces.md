### Agent Mesh S17 (G13a): unified traces across doors, workflows, agents

- One trace spine for the mesh: the trace id is the W3C trace id (#1743), minted or continued at ingress and carried — additive fields only — through the chat turn (lazy mint on the turn stash, shared by tools/doors/jobs/the NLQ screen port), the mesh door commands, the async-job queue (payload stamp + executor re-supply, mirroring the S5 actingLogin carriage), workflow start params (`WorkflowJobCommand.traceparent`, producer-stamped for the first time), screener workflow step + projection hops (deterministic spans, replay-convergent), the A2A edge (continued/minted, handed to `handleA2A` beside the S16 attribution), and the payments ledger write (trace id recorded in the `payments_agent.recorded` audit payload beside the caller).
- Hop store: AgentDB table `agent_mesh_trace_hops` (migration 0023) behind a port (D1 + in-memory adapters); recording is best-effort and never fails the traced work, and every hop also emits to the ADR 0011 observability stream with the two-part attribution.
- Read surface: `agentdb.trace.get` (MCP catalog 81) assembles one trace's ordered hops plus its mapped jobIds' projection rows, tenant-scoped via IAAA, and reports broken chains as honestly partial with named breaks.
- Registry: `MESH_TRACE_SPINE` records every carried hop and four named breaks (TradingTradeWorkflow step spans, PaymentWorkflow step spans, route-originated workflow starts, direct channel-ingress paths) with their consequences.
