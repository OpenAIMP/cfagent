### Added
- Daily enrichment + minute bars (#1888): provider-selectable enrichment system (`src/enrichment/`) — Yahoo live now, Alpaca implemented but gated OFF behind the existing feature-flag port (`enrichment_alpaca`; Flagship/env/in-memory per #1815, default off = Yahoo, flag on + keys = Alpaca-primary-with-Yahoo-fallback, flag on without keys fails safe to Yahoo). Per-provider minute validation before any fetch (Yahoo 1/2/5/15/30/60/90Min, Alpaca 1–59Min; unsupported fails explicit, never collapses to daily). Fundamentals always come from Yahoo (Alpaca has no live fundamentals — documented, never faked). Provider failure degrades to Yahoo fallback or a qualified partial via #1745 breakers, never a hard failure. Runs persist as stage-persisted job + stage records (`mas_enrichment_runs`) with coverage (requested vs served), bars fetched, fallbacks, errors, breaker state, and killswitch state. Dashboard: `GET /api/enrichment/status` + runs + run + killswitch + calibration routes and the `EnrichmentDashboard` panel in the ScreenersHub track-record tab; every run emits a `enrichment.completed` CloudEvents envelope (counts + ids only) to the #1743 stream, and quality feeds `GET /api/telemetry/summary` as the optional `enrichment` field (best-effort DO read, absent on failure). Dedicated manual killswitch (`enrichment.killSwitch` in settings, distinct from the global #756 halt — either stops this loop): thrown stops new runs and calibration proposals, manual on/off only, fail-closed on unreadable state, audited, visible on the dashboard. Calibration is propose-only per #1742's governed pattern (application is a human flag flip). Bars route canonical path is now `/market-data/bars`; the legacy path is retained as a backwards-compatible alias. No trading/account/order paths, #759 weights, or existing dashboard behavior changed.
