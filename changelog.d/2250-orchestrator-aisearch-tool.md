### Added

- Orchestrator chat tool for AiSearchAgent (#2250): a new MCP command `ai_search_agent_search` puts AiSearchAgent (#2223) in the orchestrator's chat toolset, so a chat turn can search the Cloudflare AI Search instance — the knowledge corpus, plus generated reports once #2246's indexing is enabled — through the agent itself. The tool resolves the `AI_SEARCH_AGENT` Durable Object on its fixed service instance and calls the agent's direct `search()` (the deterministic RPC door), threading the turn's verified session login as `callerLogin` so report-type results are served only to their owner; a login in tool arguments is never read (the schemas declare none), and a turn without a verified login passes no login, leaving the agent's safe default (report results withheld) in force. The agent's answer is shaped without laundering: degraded answers are stated as degraded with the agent's note carried verbatim and zero fabricated rows, and result rows keep their S2 fields and provenance. Registered with the `mcp:read` scope (#1843 table) and named in the #1763 tool-attribution audit. No SearchHub rewiring; live serving still follows the #1169 probe gate.
