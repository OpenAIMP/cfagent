### Changed
- **Schedules tab: one row per schedule, one edit action, one details dialog (#2329):** `ScheduleCard` now renders a table row instead of a grid card — job name, the **full** schedule id (the 16-character snippet is gone), cadence + next run, a one-line scope summary, and every action in one cell (`Details`, `Edit`, `Trigger Now`, `Pause`/`Resume`, `Cancel`) inside a scrollable `Table` primitive. The duplicate edit path is gone: the screening rows keep one `Edit` control (the full form, cadence included) and the generic rows open the moved `CadenceModal`; the inline preset grid was removed. `Details` opens the new `ScheduleDetailModal`, fed by the new pure `scheduleDetail.ts` model that is also the row's scope summary, so every kind (options, stock, saved-view / profile-derived / no-view discovery, system) uses one label vocabulary and order, plus the server run definition and the raw payload; a failed detail read shows the error and a retry inside the dialog. The duplicate create entry point (the tab row's `＋ New schedule` and its `openCreateSignal` plumbing) is removed — one `+ New Schedule` remains — and the page's one `↻ Refresh` now refetches the screening list, latest runs, and audit trail. Cancels and deletes confirm in one `ConfirmModal` that names the job and id. Styling moved to ui/ primitives and token-only CSS (no inline style objects, no gradient/glow button classes, no `!important` readability overrides); `LatestRunsSection` and `AuditTrailSection` render rows and lost their duplicate refresh buttons. No API, payload, trigger-route, or execution change; payload goldens untouched. Pattern recorded in `docs/architecture/UX/schedule-surface-01.md`. #autoclaw-001
