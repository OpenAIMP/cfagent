### Added
- Native subscription checkout/purchase (#2198, slice 2 of #2146, main-based rebuild superseding #2292): the subscription checkout route mints a native Stripe checkout through the CheckoutPort and returns a real checkoutUrl for card; purchase verifies by Stripe session retrieve with a mandatory amount re-check (amount_total must equal plan price × 100) and activates only on complete + paid + amount match + reference match. Both the Stripe session id and the payment-intent id are stored on the subscription row (migration 0013), so a later refund slice has the payment-intent id it needs. activateSubscription, plan records, the `sub-` prefix, the payment-reference replay guard, and cancel-at-period-end are unchanged in behavior; the cfpay /a2a/payments calls are gone from these two routes (the shared cfpay helpers stay for the slice-3 UI check-payment route).
