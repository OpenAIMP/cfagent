### Added

- Live PaymentWorkflow assurance routes (#2059): POST /api/assurance/payment-workflow/start, /event, /check-payment and GET /status. Start creates a real PaymentWorkflow instance through the PAYMENT_WORKFLOW binding with test inputs (live-test run id, TEST goal screener command, test coverage or pay-per-use account); event delivers approval/payment_verified through the binding (live-test ids only); check-payment re-reads real cfpay checkout.status and delivers the verified wake-up only when actually fulfilled. Guarded by the payment_assurance flag, caller identity, and the PAYMENT_ASSURANCE_LIVE_LOGINS allowlist (empty = deny all); checkout mode requires MONETIZATION_ENABLED and a configured cfpay key, else a 409 naming the missing piece. The assurance page gains a Live mode section next to the existing simulation.
