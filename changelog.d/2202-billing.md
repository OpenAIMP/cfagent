### Added - provider-managed recurring subscriptions via Stripe Billing (#2202, stacked on #2236)
- BillingPort + Stripe Billing adapter + composition root (null when the monetization flag is OFF or Stripe is unconfigured), port-first per ADR 0002: create/retrieve/cancel-at-period-end/cancel-immediately via the Stripe strategy (POST /v1/subscriptions, GET /v1/subscriptions/{id}, POST update, DELETE), the only Stripe API surface.
- Provider subscription id + provider status tracked on the subscription record (migration 0014), with a webhook lookup by provider id and verified-only webhook application (customer.subscription.created/updated/deleted, invoice.paid, invoice.payment_failed); unverified webhooks throw before any store touch.
- Externalized billing policy on D1 (table agent_billing_policy, migration 0014, seeded at ensure time, operator-editable with no code deploy): PROPOSED defaults pending owner approval — monthly default, monthly/annual allowed, dunning delays [1, 3, 7] days, 7-day grace, downgrade at period end, proration create_prorations, repurchase migration grandfather, empty Stripe-price map (fail closed on unmapped plans).
- No behaviour change to the live repurchase path: existing subscription checkout/purchase/cancel are untouched, the flag stays OFF, and no live recurring charge happens in this slice (draft only, for later activation).
