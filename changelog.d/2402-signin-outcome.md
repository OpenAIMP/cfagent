### Added

- Sign-in shows an outcome message for both success and failure (#2402): one allowlisted outcome channel (`auth_outcome`) shared by server and client. Callback success redirects to `/?auth_outcome=signed_in` so the app boot shows a one-time "Signed in as …" toast (shared Toast primitive) and strips the parameter; a just-created session that cannot be read back (the #2280 loop) redirects to the login page with a session_unreadable notice instead of looping silently; provider/callback failures and wiring-disabled/provider-unavailable redirect to the login page with their own user-safe notices. The failure-message path performs no SessionStore read (pure URL logic), messages carry no internals (technical cause stays in server logs/audit), and unreadable sessions are never treated as signed in. The no-outcome login page is byte-identical to before.
