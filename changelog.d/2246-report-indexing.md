### Added

- Report indexing into the AI Search instance (#2246): canonical reports are now ALSO uploaded to the Cloudflare AI Search instance at store time, behind the feature flag `AI_SEARCH_REPORT_INDEXING_ENABLED` (default OFF — flag off is today's behaviour exactly, Vectorize only). The upload rides the canonical store seams beside S4-1's Vectorize hook, through a new indexing executor in AiSearchAgent's path layer (the namespace binding's items API) and a new `indexDocument` door on AiSearchAgent. Documents are stored under the report's document id (`report:<reportId>`, the Vectorize leg's convention) with provenance metadata (kind "report", reportId, runId, ownerLogin, source, storedAt). The leg is best-effort by contract: failures are recorded with the stable code `ai_search_report_index_failed` and never fail the report store or the run; no backfill of historical reports. On the search side, report-type results are served only to the report owner's login — no login context, a mismatched login, or an unproven owner withholds the result, and the withholding is recorded in the result's degraded note. Live effect still requires the owner's dashboard steps from #2223 (the `ai_search_namespaces` binding + `AI_SEARCH_INSTANCE`), and flag-on in production follows the #1169 probe gate.
