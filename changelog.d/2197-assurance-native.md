### Assurance live rework — native Stripe (#2197) - checkout mode and status/check-payment go native
- **Assurance live rework — native Stripe (#2197, sub-issue of #2012, slice 4 of #2146, STACKED on #2195)**: `src/agents/routes/paymentAssuranceLive.ts` no longer calls cfpay at all — the last `/a2a/payments` call in this file is retired at slice 4 (design §3). Checkout mode now gates on the monetization flag read from the FeatureFlagPort (the gate's source, never the raw `MONETIZATION_ENABLED` env var) AND a configured native Stripe card port from the slice-1 composition root (`createCheckoutPorts`), with 409s naming the missing piece. Status/check-payment re-read native state via the card CheckoutPort's Stripe session retrieve; a fulfilled session (complete + paid + `client_reference_id` bound to the run) delivers `payment_verified`, anything else delivers nothing. All other guards are intact (payment_assurance flag, x-user-login identity, `PAYMENT_ASSURANCE_LIVE_LOGINS` allowlist with empty = deny all, live-test- -only ids). The start response reports `nativeStripeConfigured` instead of `cfpayConfigured`. The route-level fulfilled test cannot check the amount (it holds no price); the gate re-applies its full rule, including the amount match, when the delivered event reaches confirmPaid — the wake-up is never itself proof. Check-payment covers the card rail only (x402 has no session to retrieve; its proof goes through the /event endpoint). No activation: flag stays OFF, no live price, no mainnet charge, no key.
