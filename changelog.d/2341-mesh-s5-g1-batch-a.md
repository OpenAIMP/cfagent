### Added
- Agent Mesh S5 (#2341, programme #2225 G1 batch A): typed outbound doors from the orchestrator chat turn to ScheduledAgent and PaymentsAgent (`src/agents/orchestrator/meshDoors.ts`) with four thin turn tools — `list_scheduled_goals`, `trigger_scheduled_goal`, `check_payment_budget`, `get_payments_overview` (scopes read/write/payments/payments, #1744). Doors resolve the turn's explicit acting identity first and fail closed before dispatch when it is absent; budget checks are evaluated against the ledger's orchestrator spend bucket (`AGENTIC_SPEND_AGENT_ID`). `PaymentsAgent.processPaidRequest` is deliberately not exposed to chat (S10/G5 owns the chat paid-request flow via PaymentWorkflow). The S1 registry records the new mesh-door tool family; the acting identity is carried server-side through the MCP adapter's job stamp and the async-job executor (`McpToolContext.actingLogin`).
