### Changed
- Agent Mesh S8 (#2369, programme #2225 G2): a chat-initiated stock screen now executes as a ScreenerScreenWorkflow run. The NLQ stock-screen port (`src/agents/orchestrator/nlqPorts.ts`) starts a parent workflow command through the WorkflowPort (acting identity threaded from the async job, fail-closed — never a synthetic login), awaits the outcome on the workflow status surface (instance status + the D1 parent-row collation), and reads the full results back from the `mas_reports` canonical copies the workflow's own store step wrote — so the chat turn keeps today's results contract while the run becomes durable, resumable, and visible in jobs history / the Runs UI. Stage failures surface as failed results carrying the coded error (never a fabricated success); when the workflow port is unavailable the port keeps the legacy direct ScreenerAgent call (the route precedent). The canonical screener report body now also carries the run's `discoveryMessage`, `filterSummary`, and `rejections` so the read-back loses nothing the direct path had in hand.
