### Changed
- Agent Mesh S10 (#2378, programme #2225 G5): a chat-initiated stock screen is now a paid request when the monetization flag is on. The NLQ stock-screen port (`src/agents/orchestrator/nlqPorts.ts`) consults PaymentsAgent's budget check first — through the S5 door machinery (`checkPaymentBudgetViaDoor`), with the acting identity threaded from the async job (fail-closed before any check when identity is absent) and the catalogue-priced amount; a refusal ends the request with the guard's reason and zero workflow starts. On a pass, the request is submitted through the existing fail-closed caller seam (`paymentWorkflowSubmission`) as a PaymentWorkflow run — one charge per run-request, the payment run id IS the screener job id — with the account resolved fail-closed from the commercial/subscription stores exactly as the routes resolve it, and the result awaited on the payment workflow's own status surface plus the D1 collation and read back from `mas_reports` like the free chat path. The monetization gate's disposition inside the workflow governs exactly as configured (the port neither bypasses nor re-interprets it); unpaid/expired/rejected runs start zero screener runs and return an honest payment-state result. With the flag off, chat screens run exactly as before (free ScreenerScreenWorkflow path). No price, flag, gate, or network behavior changed; scheduled runs are untouched (subscription/credits only, never per-run charges).
