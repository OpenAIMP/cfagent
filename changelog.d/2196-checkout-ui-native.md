### Checkout UI rework for native payments (#2196, slice 3 of #2146, STACKED on #2233)
- **Checkout UI rework for native payments (#2196, sub-issue of #2012, slice 3 of #2146, STACKED on #2233, the native-gate-v2 rebuild of #2195)**: the pricing route now serves a server-derived network marker (Stripe test-vs-live mode from `StripePaymentStrategy.resolveApiKey` + the x402 network, only when the x402 checkout port exists) instead of the hardcoded `testnetOnly: true`, and an externalized browser payment scope (default `card-only`, widened by operator configuration `COMMERCIAL_BROWSER_PAYMENT_SCOPE` without a client deploy); the failure policy is now the native gate's disclosure (one-time replacement-run credit, never a cash refund promise — refund copy lands with the refunds slice #2147). The submission check-payment route is reworked from cfpay to native: card verifies by Stripe session retrieve (complete + paid + amount_total == stored catalogue price x 100 + client_reference_id == runRequestId, session resolved from the caller or the `payment.checkout_created` audit payload; display seed prices are never used for verification) and returns the native `checkoutUrl` from the retrieved session as `paymentUrl` when unpaid; x402 verifies a supplied proof via the facilitator and otherwise presents a 402 challenge-flow object (network, amount, recipient, no link — crypto has no URL). The Stripe session retrieve now passes the hosted `url` through the strategy, service, and card adapter into `CardSessionEvidence.checkoutUrl` (a redirect only, never proof), and `deliverPaymentVerifiedViaHost` now forwards `sessionId`/`paymentProof`/`payer` to the flow's confirm step. The panel renders the derived marker (Testnet badge only while no rail accepts mainnet), the card-only scope note, the native checkout link for card (pay-per-run and subscription buy, only when the server provides one), and the x402 challenge block without inventing a link; "cfpay checkout contact" copy becomes "checkout contact". No prices, flag defaults, or payment paths change; no activation (flag stays OFF, no live price, no mainnet charge, no key). The cfpay check-payment path for real runs retires with this slice; the assurance live check-payment is slice 4's scope and is untouched.
