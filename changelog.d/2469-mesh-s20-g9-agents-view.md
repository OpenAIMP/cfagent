### Agent Mesh S20 — G9: Agents view UI from the registry (#2469)

- New session-gated read route `GET /api/agents/registry` (401 anonymous, 405 non-GET): the payload is derived from the G0 registry (`src/agents/registry.ts`) at request time by a pure builder (`src/services/meshRegistryView.ts`) and served through a pure handler (`src/agents/meshRegistryRoute.ts`, the shardJobRoute shape). Every class is joined with its S15 census cells and S16 identity record; every door with its S19 cost budget; the programme records (S18 G12 proof, S17 trace spine, S19 Skills assessment) ride along. Credential posture is env names only — never secret values. The route is catalogued in the IAAA endpoint catalog (the OpenAPI spec derives from it).
- New **Agents** nav tab (appended at navOrder 25; no existing item moves) rendering that payload with ui/ primitives: per class — bindings, recorded status with the reason where degraded, door census summary, mesh credential env names — plus a per-class detail (census doors with gates/reasons, identity and credential posture), and sections for doors & budgets, workflows, channels, tool families, and programme records. The view holds no fleet data of its own: a drift pin (tests/mesh_agents_view_s20_2469.test.ts) proves the served payload equals the registry module.
- Registry extension: per-agent `status`/`statusReason` recorded on `MeshAgentEntry` — the degraded set is exactly AiSearchAgent (the `ai_search_namespaces` binding is dashboard-issued, not declared in wrangler.jsonc; namespace path config-gated) and SandboxAgent (no container backend configured; runs return `executed:false`), each pinned against the evidencing repo facts.
