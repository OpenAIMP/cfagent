### Changed

- **SlackAgent migrated to PortThink (#1960, tracker #1951):** `src/agents/slackAgent.ts` now extends `PortThink` (`src/actors/thinkAdapter.ts`) instead of `AIChatAgent`. Chat-surface mapping, verified from the class and its tests: the class defined no `onChatMessage` / `onChatResponse` / `onChatError` / `getModel` / `getSystemPrompt` / `getTools`, drove no AI chat turn, and wrote to no chat store — its "chat" is Slack webhook ingress (`onRequest` delegating to `ETradeSlackTradingService`) plus the two domain helpers, all unchanged. AIChatAgent's WS chat path therefore only ever reached its throwing default `onChatMessage`; Think's native WS chat (runTurn with Think defaults, `portHooks` unset) replaces that stub, and the `get-messages` intercept maps from AIChatAgent's stored-transcript JSON to Think's `Response.json(this.messages)` — both empty in practice, since the class writes to neither store. No port hooks existed to keep and no adapter turn is wired: inventing a model/tools/prompt would be new behavior, not a preserved turn path.
