### Fixed

- **Refreshing no longer forces a weekly sign-in for active users:** the session's 7-day absolute window now slides on an authenticated page load when two days or less remain. Renewal rewrites the same session id (other tabs stay valid), re-issues the cookie, and stops at a new 30-day hard cap (`SESSION_MAX_TTL`, measured from `firstCreatedAt`); an expired session is never renewed. The client also remembers the page being refreshed (`auth:next` in sessionStorage) and restores it after login instead of dropping to the default tab.
- **Every session/auth window now lives in `config/session-limits.json`** (typed by `src/config/sessionLimits.ts`): absolute TTL, 30-day cap, 2-day renewal window, cookie Max-Age, idle timeout (8 hours, owner override of the CISO 30-minute default), step-up freshness, touch interval, cache TTLs/entries, OAuth state and Public OAuth pending lifetimes. No session module hardcodes a duration; `SESSION_IDLE_TIMEOUT_MS` remains an optional runtime override. Step-up freshness (15 minutes) is unchanged. Pinned by `tests/session_refresh_renewal.test.ts`.
