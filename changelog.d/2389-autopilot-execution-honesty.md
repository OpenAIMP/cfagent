### Fixed
- Autopilot execution honesty (#2389): the Autopilot Control Center feed can no longer present executions no broker performed. The E*TRADE platform's draft `executeOrder` previously stamped an approved draft `executed` with a locally invented `et_ref_` reference and an estimate-derived price, with zero broker calls; it now places the order through the real broker client and persists `executed` only on a broker-confirmed result carrying a reference from an actual placement response — any other client result leaves the draft `previewed` and retryable. The E*TRADE client's non-live fall-through no longer returns a success-shaped simulated execution (`et_sim_` reference, random signature); every environment now fails honestly with no reference and no signature when no broker path executed. The Alpaca platform's hardcoded NVDA execution stub is replaced by an honest not-executed failure (the adapter has no order-placement client), and rejections still reject the stored draft. The synchronous NLQ executor no longer reports approvals as "APPROVED & EXECUTED" (with a fallback `et_fill_confirmed` reference); approvals execute only on the asynchronous NLQ path, which reports EXECUTED solely from a broker-confirmed result. Feed provenance is now derived from the record's actual broker reference: locally minted references (`et_ref_`/`et_sim_`/`alp_ref_`/`alp_exec_`) render as simulated, broker-issued references render as live, unreferenced rows make no provenance claim, and an unsigned trade record renders unsigned instead of a synthesized `sig_ed25519_` signature. Historical rows are not rewritten; rows carrying the fabricated reference prefixes are identifiable by pattern and now display as simulated. Value: the autopilot feed becomes trustworthy evidence — an EXECUTED row now means a broker actually placed the order — harvested through the Autopilot Control Center, whose badges and signatures now reflect each record's real provenance. #CDO-mha7
