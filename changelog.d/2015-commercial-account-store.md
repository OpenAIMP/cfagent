### Added

- **Minimal commercial account store on Drizzle D1 (#2015/#2020)**: `agent_commercial_accounts` (one row per user: tier, credits, included runs), `agent_tenant_settings` (per-tenant ads flag, #2022), `agent_credit_claims` (redeemable failure-credit claims, #2019), and `agent_credit_redemptions` (one-time claims), via migration 0007 in `src/data/migrationRunner.ts` and the data-foundation port pattern (`src/data/commercialPorts.ts` + `src/data/d1CommercialAdapter.ts` + `src/data/inMemoryCommercialAdapter.ts` + `src/data/createCommercialPorts.ts`). D1 is shared across instances, so there is no canonical-instance hop: routes, the payment adapter, and the ads handler build the store adapter straight from `env.AGENT_DB` (null = fail-closed on money paths, fail-open on ads reads).
- **Dedicated paid-submission route (#2015)**: `POST /payments/agentic/commercial/submit` adopts the payment workflow seam for one-off runs (recurring schedules refused — they go through the schedule service, no CTO collision) and redeems failure credits for the same family before starting the screener; `GET /payments/agentic/commercial/submission-status` reports workflow status. The payment workflow now consumes coverage (included run or credits) in the D1 store on the covered path, best-effort with loud logging so a store blip never denies a covered run, and records a D1 credit claim when a paid/covered run's screener fails (the flow's `issueFailureCredit` dep now carries the run price, mirroring the #2089 widening).
- **Ads enforcement from the store (#2022)**: the ads handlers resolve tier and the tenant ads flag from D1 via the verified login (tenant off beats tier); any store failure fails open to serve. Reconciled with #2118 (merged): #2118's viewerTier suppression and banner-config endpoint are kept, and the store now layers over them — a store record wins on tier disagreement, and tenant-off forces every banner-config allowance false while keeping the tier truthful. The banner-config client path stays with #2118 — this PR covers server lists, tracking, and the banner-config response only.

### Notes

- Email on submission is the caller's checkout contact, supplied by the caller — it is not an identity proof (no verified email exists in the session; identity is the verified login).
- Operator writes require `COMMERCIAL_STORE_OPERATORS` (empty = deny all); `AGENT_DB` must be bound or money endpoints fail closed with 503.
- The DO ledger stays the financial audit record: the D1 claim is the redeemable claim, the DO credit row (PR #2089, merged) is the audit. This PR combines both writes in `issueFailureCredit` (DO fail-loud first, then the D1 claim best-effort).
- Residual gap, stated plainly: if a credit is claimed but the screener then fails to start, the audit row is the operator re-issue signal — no operator credit-issue route exists yet.
- No client changes, no new wrangler bindings (AGENT_DB already bound), no orchestrator mount (orchestrator.ts is at its size budget — endpoints live in the existing agenticPayments handler; thin_router_inventory 247 -> 254, delegation unchanged).
