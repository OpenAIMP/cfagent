# Think vs DO agents: what existed, what changed, what was lost and gained

**Status:** Placed for issue #1926 at `docs/architecture/agentic/think-or-DO.md`. Open question O3 (the Think-port spike, §12) remains open pending a parallel spike; its verdict will be folded into this document by a later update.
**Question answered:** "Think is based upon the SDK, so how come we are not able to do everything that DO agents are able to do?"
**Short answer:** we ARE able. A Think class IS a DO agent. The premise behind ADR 0005's sentence — "the procedural half could not use actor-native features (durable state, scheduling, hibernation)" — is false as a framework claim and is corrected in §6 below. The migration's honest rationale is standardization + port + shedding an experimental opinionated layer, not capability gain.

---

## 1. Verdict up front: Think-on-SDK

| Feature | Can a Think class do it? | Source |
|---|---|---|
| Durable state (`ctx.storage`, DO SQLite, KV) | YES — inherited from `Agent`; proven in-repo: pre-#1738 `ResearchAgent` (Think) used `this.ctx.storage.sql` throughout | `node_modules/@cloudflare/think/dist/index-BLkPlEbF.d.ts:1428` (`Think extends Agent`); `git show f02c1d1c^:src/agents/research-agent.ts` lines 181, 190, 415, 418, 430–431, 496, 499, 511–512 |
| Scheduling (`schedule`, `scheduleEvery`) | YES — inherited from `Agent`; proven in-repo: pre-#1738 `OrchestratorAgent` (Think) called `this.schedule()` / `this.scheduleEvery()` | Same `.d.ts` (Think extends Agent; `schedule` 41 mentions); `git show 4b69108f^:src/agents/orchestrator.ts` lines 216, 244, 246 |
| Hibernation | YES — DO-platform behavior inherited through `Agent`; idle DOs sleep, wake on request/message/alarm, WS connections survive | Agents SDK docs, long-running agents: what survives eviction (`this.state`, `this.sql`, scheduled tasks, connection state, fiber checkpoints) vs what does not (in-memory vars, timers, open fetches, closures) — https://developers.cloudflare.com/agents/concepts/agentic-patterns/long-running-agents/ |
| WebSocket chat | YES — natively; Think owns the WS chat protocol (`useAgentChat`) | Think README + docs index: "top-level agent (WebSocket chat protocol for browser clients)" — https://developers.cloudflare.com/agents/harnesses/think/ |
| Turn recovery (durable turns) | YES — and BETTER than the repo's actor runner: Think wraps turns in recoverable fibers; eviction mid-stream reconstructs buffered chunks, persists partial output, schedules continuation/retry; `chatRecovery` / `onExhausted` bound the path | Think docs, durable recovery — https://developers.cloudflare.com/agents/harnesses/think/recovery/ ; Think 0.19.0 docs `lifecycle-hooks.md`, `index.md` ("Durable turns", "Recovery-aware delivery") |
| Session model | YES — tree-structured sessions with branching, compaction, full-text search (ThinkSession), vs the actor runner's flat upsert-by-id transcript | Think 0.19.0 docs `index.md` ("Sessions, not just a message list"), `lifecycle-hooks.md` (`configureSession`, `configureContext`) |
| Tool execution | YES — same model/tools/instructions/step bound; Think adds MCP auto-conversion, client tools, codemode/shell workspace tools, Agent Skills | Think 0.19.0 `index.md` config table (`getSkills()`, `getSkillScriptRunner()`), README (codemode, shell, chat SDK deps) |
| Agent-as-a-tool | YES — three layers: SDK `runAgentTool` (the repo's primary dispatch, base-independent), SDK `subAgent()` / dynamic child DOs, Think `chat()` sub-agent RPC | `src/agents/orchestrator/researchPublish.ts` (`ctx.runAgentTool(ResearchAgent, …)` pre- AND post-#1738); Think 0.19.0 docs `sub-agents.md`; `node_modules/agents/docs/sub-agents.md` |

**The one-sentence correction:** Think does not sit *beside* the Agents SDK; it sits *on* it. `Think<Env, State, Props> extends Agent<Env, State, Props>`, in the same `cloudflare/agents` monorepo (`packages/think`), peer-depending on `agents >=0.24.0 <1.0.0`. Everything a DO agent can do, a Think class can do — plus Think's own chat layer. What the repo's Think classes did *not* do was go through a repo-owned actor port, and their chat turns went through Think's session/turn layer rather than direct actor primitives. That is a usage-pattern fact, not a framework ceiling.

**Is Think "the latest framework"?** Both readings, honestly: Think is the newest *product surface* (Project Think blog, 2026; "we're already using it internally to build our own background agent infrastructure, and we're sharing it early"). But it is NOT the stable going-forward standard: its own README and docs index flag it **Experimental** ("the API surface is stable but may evolve before graduating out of experimental"), and the docs site files it under Agents docs as a *harness* (`/agents/harnesses/think/`). The Agents SDK is the foundation; Think is the opinionated chat layer on top of it. The repo pins `@cloudflare/think` 0.19.0 and `agents` 0.24.0.

## 2. What existed (pre-#1738)

### 2.1 Timeline (correcting the baseline snapshot)

- **2026-10-20 baseline** (`docs/agents/think-roles-decision.md` inventory): `ResearchAgent` = Think; `OrchestratorAgent` = AIChatAgent with a manual `streamText` loop; `BrowserAgent`/`SlackAgent` = AIChatAgent; `PaymentsAgent`/`ScheduledAgent`/`ScreenerAgent` = `Agent`; `OptionsScannerMCP` = `McpAgent`; `SessionStore` = plain `DurableObject`. Four unreferenced AIChatAgent prototype classes (`search`/`tasks`/`memory`/`payments.ts`) also existed (finding F5).
- **Then:** `OrchestratorAgent` cut over onto Think in #686 step 4; `TradingAgent` was created as a Think agent (#291 T1). So by #1738 the Think set was three classes: Orchestrator, Research, Trading. The "only ResearchAgent was Think" line is the 2026-10-20 baseline, NOT the pre-#1738 state — do not quote it as the latter.
- **Think version + adoption state at #1738:** `@cloudflare/think` 0.19.0, `agents` 0.24.0. Think adoption was PARTIAL as a *conformance* matter (the plan's §2 designation question was unresolved until the roles decision marked ResearchAgent Required and OrchestratorAgent Optional-then-migrated), but as a *code* matter three live classes extended Think and all of them were already bound DO classes (`RESEARCH_AGENT`, `SEARCH_AGENT` via the OrchestratorAgent alias, `TRADING_AGENT`) with `new_sqlite_classes` migrations. They were Durable Objects. "Procedural" in ADR 0005 describes their code style and the absence of a port — not a non-DO runtime.

### 2.2 The two runtimes, precisely

- **Agents SDK actors:** `ScreenerAgent`, `ScheduledAgent`, `PaymentsAgent`, `ReportAssetAgent` extended `Agent<Env>`; `BrowserAgent`/`SlackAgent` extended `AIChatAgent<Env>`.
- **Think classes:** `OrchestratorAgent`, `ResearchAgent`, `TradingAgent` extended `Think<Env>`.
- **What the Think classes actually did with actor primitives (git evidence, the crux):**
  - `ResearchAgent` (Think) executed raw DO SQL through `this.ctx.storage.sql` and used `this.ctx.storage` blob storage across its pipeline (pre-#1738 file, lines cited in §1).
  - `OrchestratorAgent` (Think) armed schedules through `this.schedule()` / `this.scheduleEvery()` (pre-#1738 file, lines cited in §1).
  - Both used Think's session/turn layer for chat: Think session assembly, `runTurn`, `beforeTurn`/`onChatResponse`/`onChatError` hooks (the class's own methods, unchanged by #1738), `configureContext` session-memory blocks, `waitUntilStable`, `activeTurnMetadata`.
  - Neither went through a repo-owned port — there was no port. That absence, not a framework bar, is what #1738 fixed.

### 2.3 Think conformance state at the time

`docs/agents/think-conformance.md` (assessment baseline main `f063104`, 2026-10-20; epic #539; plan `docs/agents/cloudflare.md` §14 output): Think adoption PARTIAL; version/API compatibility PARTIAL (pinned after PR #548 closed F1); functional completeness UNKNOWN (not assessed feature-by-feature); security/isolation PARTIAL; reliability/recovery PARTIAL (bounded steps everywhere, deterministic fallback — but the fallback could silently bypass Think, F4; restart/reconnect behavior of Think turns not exercised); operational readiness PARTIAL (no production observation available). Findings: F1 floating `latest` specs (CLOSED by #540/PR #548); F2 designated Think roles unspecified (open, #545 — later resolved by the roles decision); F3 Think-path test evidence was a stub — vitest replaced `@cloudflare/think` with a minimal stub class, so deleting the Think import, the DO export, or the `RESEARCH_AGENT` binding would not fail any test (open, #542); F4 research fallback silently bypasses the Think turn (open, #543); F5 agent identity naming hazards (SEARCH_AGENT runs OrchestratorAgent via alias; two classes named PaymentsAgent); F6 orchestrator monolith (2,802 lines at baseline; incremental extraction, not big-bang). The roles decision's test is worth quoting: "Think is a *chat harness*: it owns the agentic chat loop, message persistence, streaming, and tool interaction. A role gains from designation only where that ownership replaces a hand-rolled equivalent."

## 3. What changed (#1738: PR #1812, ADR 0005)

- **Class-body migration:** `OrchestratorAgent`, `ResearchAgent`, `TradingAgent` moved `Think<Env>` → `Agent<Env>` (orchestrator commit `4b69108f`, 162 insertions / 39 deletions in one file; actor-port commit `f02c1d1c` carrying the port + ADR + suites). No binding changed, no migration changed: all seven actor classes were already bound; the migration is class-body only, verified by conformance-suite wrangler pins.
- **The port (`src/actors/`):** `ActorStatePort` (KV + `sql` escape hatch for the DO SQLite tables the class already owns), `ActorSchedulePort` (schedule/scheduleEvery/list/cancel by method name), `ActorSessionPort` (transcript: `getMessages`, `appendMessages` upsert-by-id with Think `saveMessages` semantics, `deleteMessages`, `migrateLegacyRows`, `clear`), `ActorTurnPort` (one method, `runTurn`), `ActorTurnHooks` (`getModel`, `getSystemPrompt`, `getTools`, `beforeTurn`, `onChatResponse`, `onChatError`, `maxSteps`). Two adapters implement it, one conformance suite runs unchanged against both: `cfAgentsAdapter.ts` (Agents SDK: session over `ctx.storage` KV, state over `ctx.storage`, schedule delegated to the SDK scheduler, turns through the shared runner with the production `generateText` model turn) and `inMemoryActorAdapter.ts` (Map/array-backed; turns through the SAME runner with a stubbed provider boundary — the lifecycle is not stubbed, only the model call). Factory `createActorPorts.ts` (`"cf" | "in-memory"`).
- **Honest boundary (ADR 0005 A1):** the actor classes themselves import `{ Agent }` from `"agents"` — subclassing requires it. The port rule binds everything else: no route, service, tool, or pipeline module imports the SDK directly; all behavior beyond the framework overrides goes through the port. "The class declaration is the adapter; the logic is not."
- **The shared turn runner (`actorTurnRunner.ts`, `AgentChatTurnRunner`):** normalize input → upsert delta into session → `beforeTurn` (skipped on `configOverride`) → one model turn, AI SDK `generateText` with the hook's model/system prompt/tools and the step bound as `stopWhen: stepCountIs(maxSteps)` (AI SDK 7 has no `maxSteps` option; this is exactly the bound Think enforced) → unless an abort gate fires, append the assistant message and fire `onChatResponse` (assistant `mas_messages` record, judge evaluation → `response.evaluated` audit, best-effort VectorMemory remember — the live streamText onFinish side effects, preserved) → on model failure fire `onChatError` and rethrow. Model messages are a text-only mapping; tool parts stay in the transcript at full fidelity and are not replayed to the model.
- **Session move (A4):** Think Sessions / ai-chat SQLite → actor `ctx.storage` transcript keys (`actor:session:message:<id>` + `actor:session:index` ordered-id list). Same UIMessage shape; legacy-row transform moved from the #658 test harness into production code; `migrateLegacyRows` imports `cf_ai_chat_agent_messages` rows by id and drops the table only on a fully clean lift; `mas_messages` audit records unchanged.
- **Abort/reset reimplementation (A5):** the memory-reset route needed three Think methods that do not exist on `Agent` — `abortAllRequests`, `resetTurnState`, `clearMessages` — reimplemented on the class with separate scopes: `abortAllRequests` bumps a turn epoch (the runner checks it before appending and before `onChatResponse`, so a reset cannot land a stale turn's side effects); `resetTurnState` clears the in-flight `pendingTurn` stash; `clearMessages` clears the actor transcript only (`mas_messages` audit rows untouched, as before).
- **Labels + vocabulary (A6):** research dispatch label `executionPath "think"` → `"agent"` everywhere; primary path still the SDK's `runAgentTool`; direct-pipeline fallback unchanged; CloudEvents v1.0 envelopes + stage-typed job commands + slice-2 `agent_shard_jobs` model consumed, not reinvented.
- **What did NOT change:** `ThinkWorkflow` classes (both workflow classes still `ThinkWorkflow` by ADR 0004 W13; the `@cloudflare/think/workflows` alias stays; the bare `@cloudflare/think` vite alias + test stub were deleted); the trade workflow's agent type parameter → `any` (W13: it never called agent methods); `getScreenerAgent`/`getResearchAgent` duplicates NOT collapsed (that dedup belongs to #1717 S5 actor-gateway port #1779, CISO lane — gateway vs runtime, complementary not competing); S6 workflow-port convergence (#1780) untouched (actors consume WorkflowPort commands; the turn facet is independent of which workflow adapter runs the job).
- **Verification claimed:** verify-before-merge OK (604 files / 6877 passed / 1 skipped at landing); gate 12/12; post-merge CI 16/16 incl. PROD deploy + QA + secrets sync + Tag Release + 4 shards; §15 6423355626; #1738 closed; live-production actor-turn verification NOT claimed (pinned by port conformance + cutover suites; confirm on deployed Worker).

## 4. What was lost (D1–D6, with mitigating facts and one correction)

- **D1 — WebSocket chat transport removed.** Think's native WS chat went with the base change. Mitigating fact: no in-repo client used it (no `useAgentChat`, no WS URL in `src/client/`); POST `/api/chat` + MCP JSON-RPC remain the supported chat entries. An external WS client would break. Follow-up if wanted back: an AIChatAgent-based WS chat front-end (per ADR 0005; a Think-based WS front-end is the other route — see §10).
- **D2 — Turn recovery is in-memory only. CORRECTION to scope:** Think seals interrupted turns (`chatRecovery`, `onExhausted`) via recoverable fibers — "Think always wraps chat turns in recoverable fibers. If the Durable Object is evicted mid-stream, Think reconstructs any buffered chunks. It persists partial output and schedules a continuation or retry" (Agents docs, durable recovery). The actor runner does not: `pendingTurn` is in-memory and re-derived; POST turns are request-scoped, so a DO eviction mid-turn drops the turn instead of resuming it; the route's degraded fallback still covers the client-visible failure. **But:** the repo's own HTTP-driven orchestrator turns already used an in-memory `pendingTurn` stash under Think too (migration diff comment: "One in-flight chat turn per DO instance is the live semantic"; "Issue #1738: the stash is in-memory only; there is no durable turn sealing on eviction"). So for the repo's actual HTTP turns, D2 changed nothing observable — the loss bites Think-driven turns (WS chat, `saveMessages` admissions, auto-continuation), not the HTTP path. **And:** plain Agents CAN build durable turns — the SDK's `runFiber()` registers a task in SQLite, checkpoints via `stash()`, and calls `onFiberRecovered()` on next activation after eviction (Agents docs, durable execution). The repo's runner simply does not use it. D2 is a runner gap, not an Agent-framework gap.
- **D3 — Session store move.** Think Sessions / ai-chat SQLite → actor `ctx.storage` keys. Behavior-preserving shape (same UIMessage); the loss is Think's session *model*: tree-structured history with branching, compaction, and full-text search (ThinkSession) replaced by a flat ordered-id transcript. Compaction (with `onCompaction` + auto-compact-after-threshold) and session search went with it.
- **D4 — Research dispatch label.** Primary path stays `runAgentTool` (SDK method, not a Think method). Only the label changed. No capability lost.
- **D5 — `waitUntilStable` becomes a `pendingTurn` poll.** Same call site, same best-effort catch, same 30 s default timeout, 100 ms interval; returns whether the stash cleared. No Think turn-lifecycle primitive backs it anymore. No capability lost, one primitive less.
- **D6 — Model-turn internals.** Streaming, recovery fibers, and continuation coalescing collapse into a single `generateText` turn with the same model/tools/instructions/maxSteps/activeTools. WS streaming goes with D1; the HTTP path returns the same final text; `onChatResponse` side effects preserved.
- **Beyond D1–D6 — hook granularity lost (evidenced, not in the ADR's delta list):** Think's lifecycle hooks fire on every turn regardless of entry path — `configureSession`, `configureContext`, `beforeTurn`, `beforeStep`, `beforeToolCall`, `afterToolCall`, `onStepFinish`, `onChunk`, `onChatResponse`, `onChatError`, `classifyChatError` (Think 0.19.0 `lifecycle-hooks.md`). The actor runner keeps four: `beforeTurn`, `onChatResponse`, `onChatError` (+ model/prompt/tools/maxSteps). Lost: per-step hooks, per-tool-call gating/observation, per-chunk streaming hooks, error classification (`classifyChatError` with reactive context-overflow handling), and context-block merging — the orchestrator's `configureContext` session-memory block (top-8 `mas_memory` facts, merged into every turn under Think) became a dead resolver under the runner ("under the actor turn runner nothing merges it — the live prompt already inlines the identical content via assembleGrounding"). That content survived via a different path; the *mechanism* did not.
- **Not lost (correcting a possible misreading):** durable state access, scheduling, hibernation, `runAgentTool` dispatch, `getScreenerAgent`/`getResearchAgent` accessors, A2A dispatch (binding-level), MCP surfaces, Workflows (ThinkWorkflow untouched), the `mas_*` audit/ledger tables, the judge evaluation + audit side effects, VectorMemory remember, the direct-pipeline fallback.

## 5. What was gained (and what is port-gain vs base-gain — separated honestly)

- **Single pattern.** Two runtimes (Agents SDK actors + Think classes, plus AIChatAgent manual loops) → one documented `AgentActorDO` pattern (naming: role + `Agent`; binding: `ROLE_AGENT`; state ownership: DO `ctx.storage` authoritative for actor state). New work learns one pattern. This is the largest real gain and it is a standardization gain, not a framework-capability gain.
- **Port + independence proof.** `src/actors/` port, two adapters, one conformance suite run unchanged against both; the test harness for agent turns is the in-memory actor adapter, not a framework stub (contrast finding F3: vitest replaced `@cloudflare/think` with a minimal stub class, so deleting the Think import, the DO export, or the `RESEARCH_AGENT` binding would not fail any test). **Honesty note:** the port is a repo pattern, not an Agent-exclusive feature. In principle a port could have been built over Think's session/turn APIs too (no such spike was run — see open question O3). What the migration actually bought was a port *implemented against* the stable SDK surface, without Think's opinionated session/turn layer in the middle. The independence proof is real; its attribution to the base change (rather than to the port discipline itself) is partial.
- **Repo-owned runner.** The turn lifecycle is now repo code: the runner, the session store, abort/reset semantics, the text-only model mapping. The team can change it without waiting on an experimental package's API evolution. Cost of that ownership: D1, D2, and the hook granularity in §4.
- **Direct actor-primitive access — clarified, not gained.** The ADR's phrasing ("could not use actor-native features") inverts the truth: the repo's Think classes already used `ctx.storage` and `schedule()` directly. What changed is that *all* actor behavior now goes through one owned surface instead of partly through Think's layer. Directness of access improved; access itself did not newly appear.
- **Blueprint direction.** Compliance with SARB-approved blueprint ADR-0004 (Approved): "Wrap every agent domain in a stateful Durable Object implementing the Cloudflare Agents SDK framework" — consequences claimed: persistent agent memory, WebSocket streaming, stateful tool orchestration, actor-isolated security bounds. Note the blueprint's complaint is about *procedural* classes, and its "WebSocket streaming" consequence is one Think already provided — the blueprint direction is about standardization on the SDK, not about Think lacking WS.
- **Level 4 precondition (taxonomy §5/§11).** System at Maturity Level 3 (autonomous task execution with HITL safeguards); roadmap to Level 4 (closed-loop weight optimization, dynamic prompt optimization, champion-challenger promotion, self-healing patching) needs durable actor state as its precondition (DO SQLite prompt registries, sandbox shadow runs). Actor DOs are that precondition. **Honesty note:** Think classes, being DOs with `ctx.storage`, could also host prompt registries — the precondition is "durable DO state behind one pattern," which the migration delivers by standardization, not by a feature Think lacks.
- **Shedding an experimental dependency for the agent base.** Think's API is stable but explicitly may evolve before graduating out of experimental; the agent base no longer rides that evolution risk. (Think remains a dependency for workflows — the exposure is reduced, not removed.)
- **Downstream consumers built on the port since #1738** (these are gains *of the port*, and would need rework on revert — see §10): #1740 retrieval grounding on actor turns (graph expansion section appended when rows exist; failure degrades to dense-only, logged); #1742 telemetry/calibration beforeTurn plug (`calibratedPromptPlug`: actor-port beforeTurn implementation; falsification-gated engine); #1741 actor-turn gateway routing (gateway model turn runs inside the actor runner without replacing the actor port); #1744 agent-turn permission gating (agent-turn adapter as a choke point, scope enforcement on tool calls from turns).

## 6. Corrections to prior chat claims (explicit)

- **C1 — "The procedural half could not use actor-native features (durable state, scheduling, hibernation)." CONTRADICTED as a framework claim.** Think extends Agent (package source, §1). The repo's own Think classes used `this.ctx.storage.sql` (ResearchAgent) and `this.schedule()`/`this.scheduleEvery()` (OrchestratorAgent). Hibernation is DO-platform behavior inherited through Agent. **Corrected claim:** the repo's Think classes did not go through a repo-owned actor port, and their chat turns went through Think's session/turn layer rather than direct actor primitives. The migration rationale is standardization + port + shedding an experimental opinionated layer — not capability.
- **C2 — "Procedural" ≠ non-DO.** The pre-#1738 Think classes were bound DO classes with `new_sqlite_classes` migrations. "Procedural" described code style (and, for the AIChatAgent-era orchestrator, hand-rolled loops) and the absence of a port — not a separate runtime outside Durable Objects.
- **C3 — Timeline precision.** "Only ResearchAgent extended Think" is the 2026-10-20 baseline (roles decision), not the pre-#1738 state. By #1738, three live classes extended Think (Orchestrator via #686 step 4, Trading via #291 T1, Research). Quoting the baseline as the pre-migration state understates Think adoption and overstates the migration's starting gap.
- **C4 — D2 scope.** "Think sealed interrupted turns; the actor runner does not" is true as a runner comparison, but the repo's HTTP-driven orchestrator turns used an in-memory stash under BOTH bases — D2 changed nothing observable on the HTTP path. And plain Agents can build durable turns via `runFiber()`; the runner's gap is a wiring choice, not a framework ceiling.
- **C5 — "Agent provided durable state/scheduling/hibernation that Think couldn't." REVERSED.** Think had all three by inheritance. What the Agent base provided was directness, a repo-owned runner, and freedom from an experimental API — not the features themselves.
- **C6 — "No Think class remains" needs its qualifier.** True for *agent* classes. False for the repo: both workflow classes are still `ThinkWorkflow`, `@cloudflare/think` is still installed and imported by the workflows path, and the `@cloudflare/think/workflows` alias stays. Think was removed from the agent base, not from the repo.

## 7. Capability matrices (both directions, sourced)

### 7.1 What Think agents can do (or do better) that plain DO agents cannot — or can only by hand-building

| Capability | Think | Plain Agent (repo runner) | Source |
|---|---|---|---|
| Durable turns (eviction-safe) | Built in: turns wrapped in recoverable fibers; buffered chunks reconstructed; partial output persisted; continuation/retry scheduled; `chatRecovery` + `onExhausted` bound the path | Not built in: `pendingTurn` in-memory; eviction drops the turn; degraded fallback covers the client-visible failure only | Agents docs, durable recovery; ADR 0005 D2; `actorTurnRunner.ts` |
| Recovery-aware delivery | Replies snapshotted `accepted`/`streaming`/`completed`; restart replays a not-yet-streamed answer, posts a safe interruption notice instead of a duplicate partial | No equivalent: HTTP path returns final text or falls back; no delivery snapshots | Think 0.19.0 docs `index.md` ("Recovery-aware delivery"), `messengers.md` (delivery + recovery) |
| Durable submissions | `submitMessages()`: durable acceptance boundary with idempotency key; caller returns fast, retries safely, inspects result later; declarative scheduled prompt tasks (`getScheduledTasks()`) ride the same path | No equivalent in the runner; scheduled work goes through ScheduledAgent/cron + WorkflowPort, not a turn-submission API | Think 0.19.0 docs `programmatic-submissions.md` |
| Tree sessions | Branching history, compaction (`onCompaction`, auto-compact-after-threshold), full-text search over sessions | Flat ordered-id transcript; no branching, no compaction, no session search | Think 0.19.0 docs `index.md` ("Sessions, not just a message list"), `lifecycle-hooks.md` (`configureSession`) |
| WS chat protocol | Native WS chat + `useAgentChat` client; same protocol as `@cloudflare/ai-chat`, existing UI components work unchanged | Removed (D1); POST `/api/chat` + MCP JSON-RPC only | Think README; Agents docs Think page; ADR 0005 D1 |
| HITL + client tools | A turn can pause for approval or a browser-side tool and resume later without holding a request open | No turn-pause primitive in the runner; approvals live outside turns (approval engine, HITL gates on routes) | Think 0.19.0 docs `index.md` ("Human-in-the-loop and client tools") |
| Messengers | Owns messenger ingress directly (`getMessengers()`; Telegram adapter in 0.19.0): webhook route, durable reply fiber, conversation routing, streamed delivery | No messenger ingress in the runner; channel surfaces (Slack/email/voice) are separate adapters on the NLQ pipeline | Think 0.19.0 docs `messengers.md`, README |
| Workspace + sandboxed tools | Codemode sandboxed execution, shell workspace/file tools, `state.*`/`git.*` providers as Think tools | Not in the runner; tool surface is the repo's MAS tool factory + MCP tools | Think 0.19.0 docs `index.md` (related packages), README (deps: codemode, shell) |
| Agent Skills | On-demand skill catalog (`getSkills()`; `activate_skill`, `read_skill_resource`, optional `run_skill_script`); failing/duplicate sources skipped with a warning | No skill catalog in the runner | Think 0.19.0 docs `index.md` §Agent Skills, `getting-started.md` |
| Hook granularity | Per-step (`beforeStep`, `onStepFinish`), per-tool-call (`beforeToolCall` with ToolCallDecision, `afterToolCall`), per-chunk (`onChunk`), error classification (`classifyChatError`) | `beforeTurn`, `onChatResponse`, `onChatError` only | Think 0.19.0 docs `lifecycle-hooks.md` vs `actorTurnRunner.ts` |
| Context blocks | `configureContext()` blocks merged into every turn (e.g. session-memory facts) | No merging in the runner (orchestrator block survives as a dead resolver; content inlined elsewhere) | Think 0.19.0 docs `lifecycle-hooks.md`; orchestrator migration diff `4b69108f` |
| Sub-agent RPC | `chat()` runs a full turn (persist user message, agentic loop, persist response) with streamed events via callback; each child gets its own conversation tree, memory, tools, model | `runAgentTool` (SDK, shared) + `subAgent`/dynamic child DOs (SDK, shared) — Think's `chat()` surface itself is Think-only | Think 0.19.0 docs `sub-agents.md`; Cloudflare blog, Project Think (sub-agent RPC) |

### 7.2 What DO agents can do (or do better) that Think agents cannot — or can only by fighting the layer

| Capability | Plain Agent (repo runner) | Think | Source |
|---|---|---|---|
| Stable, non-experimental base | Agents SDK stable surface; no "may evolve before graduating" caveat on the agent base | Experimental API by its own README/docs; surface may evolve before graduating | Think README + docs index ("Experimental") |
| Repo-owned turn lifecycle | Runner, session store, abort/reset semantics are repo code; changeable without upstream evolution | Turn lifecycle owned by Think (fiber wrapping, session assembly, recovery policy); customization is via hooks/config, not ownership | ADR 0005 A3/A5; Think docs `lifecycle-hooks.md` |

## 8. Why Think agents are better than DO agents — and why DO agents are better than Think agents

**Think is better where the work is conversational, long-lived, and interruption-prone.** A Think agent's turn is a durable object in the strong sense: fiber-wrapped, checkpointed, recoverable across eviction, deploy, and stalled streams, with delivery snapshots that prevent duplicate partials and a bounded-exhaustion path (`onExhausted`, terminal message) instead of silent loss. Its session is a tree, not a list — branches, compaction, and search are first-class, which is what a coding/research agent's memory actually looks like over weeks. Its turn can pause for a human approval or a browser-side tool and resume later without holding a request open, and it can own messenger ingress end-to-end. It arrives with a catalog of hard-won chat machinery (WS protocol, stream resumption, message sanitization, durable submissions with idempotency keys, scheduled prompt tasks, Agent Skills, codemode/shell workspace tools) that a hand-built runner must re-derive one bug at a time. For a top-level chat agent or a sub-agent driven over RPC, Think is the higher-level, more complete machine — that is literally its design brief ("for agents whose work must outlive the request").

**DO agents (plain Agent + repo runner) are better where the work is owned, measured, and composed.** The base is stable, not experimental, so the agent's core does not ride another package's graduation risk. The turn lifecycle is repo code, which means the team can see, test, and change every step — and test it without the framework, via the in-memory adapter, with the lifecycle (not a stub) under test. The transcript store shape is the repo's choice, the abort/reset scopes are exactly the scopes the memory-reset route needs, and the gateway model turn composes beside the runner instead of inside someone else's pipeline. The dependency surface is smaller, the failure modes are fewer and locally understood, and the whole thing sits behind a port with a conformance proof — so a future provider swap touches adapters, not agent logic. For pipeline agents (screening, scheduling, payments, ledger work) that never needed a chat harness at all, plain Agent was always the correct base (roles decision §8G: unused framework features are NOT APPLICABLE, not gaps) — Think would have added a chat harness to non-chat responsibilities.

**The honest synthesis:** Think is a superset machine with an experimental label; the DO-agent pattern is a subset machine with full ownership. The migration traded Think's chat machinery for ownership + standardization. Whether that trade was right depends on which agent you mean: for the orchestrator's HTTP-driven turns (in-memory stash under both bases, content inlined elsewhere, no WS client), the trade cost almost nothing observable; for a future WS-first or long-turn agent, the trade re-bought work Think already did.

## 9. Why a transition back to Think would lose the ActorDO gains

**What would be lost (mechanical):**
- The actor port itself (`src/actors/`): facets, both adapters, the factory, and the conformance suite run unchanged against both. A revert must either throw the port away or rework it onto Think's session/turn APIs (`saveMessages`/`chat()`/`submitMessages`/ThinkSession instead of `getMessages`/`appendMessages`/`runTurn`) — the port as built is shaped to the runner, not to Think.
- The shared turn runner and its hook surface (`beforeTurn` → single `generateText` → `onChatResponse`/`onChatError`, abort epoch, text-only model mapping, tool-part fidelity). Think's pipeline would replace it, including its own step bound, streaming, and recovery policy — the repo's exact abort/reset scoping (A5) would be re-derived against Think's methods.
- The session-store shape: actor `ctx.storage` keys + ordered-id index + legacy-row lift as production code, replaced by ThinkSession's tree store; a migration back (or a dual-read) would be needed for existing transcripts.
- The downstream consumers built on the port since #1738, each needing rework onto Think's lifecycle: #1740 retrieval grounding on actor turns; #1742 telemetry/calibration beforeTurn plug; #1741 actor-turn gateway routing; #1744 agent-turn permission gating (the agent-turn choke point). None of these call Think APIs today.
- The single pattern: back to two runtimes (Agents SDK actors + Think classes) and the "new work must learn both" cost that motivated #1738 — plus the roles-designation question (which roles must be Think?) reopening.
- The independence proof: Think-path test evidence was a stub (F3) — the repo would need a new conformance story for the Think path, or accept the stub gap again.

**What would be regained (mechanical):** D1 (WS chat + `useAgentChat`), D2 (fiber-wrapped durable turns + recovery-aware delivery + `chatRecovery`/`onExhausted`), durable submissions + scheduled prompt tasks, tree sessions with branching/compaction/search, HITL + client tools, messenger ingress, codemode/shell workspace tools, Agent Skills, per-step/per-tool-call/per-chunk hooks, error classification, context-block merging.

**What would NOT be lost (to prevent overclaiming):** durable state access, scheduling, hibernation, `runAgentTool` dispatch, `subAgent`/dynamic children, A2A dispatch (binding-level, base-independent), MCP surfaces, Workflows (ThinkWorkflow untouched either way), `mas_*` audit/ledger tables, judge evaluation + audit side effects, the direct-pipeline fallback. A revert changes the chat layer, not the platform capabilities.

**Decision-level note:** reverting overturns two approved decisions, not one code choice: blueprint ADR-0004 (SARB-approved: "Wrap every agent domain in a stateful Durable Object implementing the Cloudflare Agents SDK framework") and #1738's acceptance criterion ("No `Think<Env>` agent class remains"). It also reopens epic #539's conformance program (F2's designation question, F3's stub evidence, F4's silent-bypass finding). That needs a superseding decision with the same standing as the decisions it overturns — an owner decision recorded on #1926 (or a successor), not a quiet refactor inside another slice. The revert itself, if directed, is a program of work (port rework + session migration + consumer rewiring + conformance story), sequenced issue → PR → merge → verify like #1738 was.

## 10. Full agentic analysis

### 10.1 Agentic Enterprise (self-governing, self-evolving)

Self-governing, partially; self-evolving, no — and the boundary is deliberate. Self-governing machinery in place: falsification-gated calibration (#1742: thesis slice with ≥20 evaluated samples + falsificationRate > 0.5 proposes a calibration note from a frozen snapshot; a human non-proposer approves; a different human applies; the engine never rewrites prompts itself); circuit breakers (#1745: trip → fallback → probe → recover; open breaker = zero budget/calls); shard timeouts → qualified partials (#1737 vocabulary); the adaptation kill switch + the enrichment killswitch (manual on/off only, fail-closed, audited); the shared approval engine (#1262: email/Slack/voice approvals, signed links, bare APPROVE refused on the production path); HITL gates on trade preflight. Self-evolving machinery NOT in place: no unsupervised prompt rewriting, no unsupervised weight rewriting, no code mutation by agents; taxonomy Level 3 limitations state it plainly (fixed prompt templates; reflection logs stored but do not mutate agent code or prompt instructions without developer intervention). The RSI loop is therefore measure → report → propose → human approve → apply — a governed loop, not an autonomous one. Think's contribution to this picture would be durability of the loop's turns (fiber-wrapped turns survive eviction) and Agent Skills as an on-demand capability catalog; the DO pattern's contribution is the governed hooks (beforeTurn calibration plug, telemetry projection, permission gating) that keep the loop human-gated.

### 10.2 Agentic architecture

Port-first, hexagonal in the repo's own dialect: every Cloudflare surface behind a port + provider adapter + second adapter or documented seam + conformance suite (messaging #1739, workflows #1737, actors #1738, retrieval #1740, gateway #1741, telemetry #1742, observability #1743, permissions #1744, breakers #1745, D1 data layer #1546). DO state is authoritative; D1 is a read projection; CloudEvents v1.0 is the envelope standard (eventId = idempotency key) unless a reasoned exception is recorded; choreography at the edges (pub/sub domain events with adapter fan-out) + orchestration sagas in the middle (multi-step workflows, resumable, parent/child fan-out with collation); synchronous paths kept for HTTP responses, HITL approvals, and trade preflight. The actor port is the agent-runtime facet of this architecture; the S5 actor-gateway port (#1779, CISO lane) is the complementary dispatch facet (how code reaches a DO instance), deliberately not collapsed into the runtime port. Think's place in this architecture, if restored, would be as one more adapter implementation behind the actor port — not as a competing architecture — but its session/turn APIs would force the port's session/turn facets to be re-expressed, which is the revert cost in §9.

### 10.3 How autonomous the system is (autonomous subsystems)

Autonomous today (no human in the loop): ScheduledAgent cron goals (synthesized schedules fire, delegate to orchestrator, budget-checked by PaymentsAgent); scheduled screener runs (hourly NASDAQ100 stock + options screens, sharded, collated, delivered to Slack, reports stored); breaker trips/fallbacks/probes; shard timeout → qualified partial; retry with backoff; enrichment runs (route-driven; scheduled-screen cutover NOT done — enrichment into scheduled Feed/Gather stage jobs is a follow-up); telemetry projection (`evaluateRun` automatic, best-effort); retention purge definition (not a live job). Human-gated by design: trade execution (approval engine + HITL gates + preflight); calibration application (propose → approve → apply, applier ≠ approver allowed, proposer never approver); prompt-note application; killswitch/halt flips (manual only); chain promotion (Phase 3 approval for the chain's content + staged rollout shadow → partial → full, ADR 0014); canonical report deletion (platform-admin only); seed invokes (operator-only routes, never boot/deploy/tick). The honest autonomy summary: the system is autonomous in *execution* (runs, retries, fallbacks, projections) and governed in *change* (nothing that alters prompts, weights, code, or money moves without a human or a human-set switch). Think vs Agent does not change this map — both bases execute under the same gates — except that Think's durable turns + durable submissions would make autonomous execution more interruption-proof, and its HITL pause/resume would make one more human gate expressible inside a turn rather than outside it.

### 10.4 Agentic topology

Hub-and-spoke with choreographed edges and orchestrated middles. Hub: OrchestratorAgent (exported as SearchAgent) — top-level chat + coordination, NLQ dispatch, judge routing, MAS tool factory, report publishing. Spokes/roles: ResearchAgent (options research, deterministic pipeline + Think-era tool dispatch now via `runAgentTool`), TradingAgent (trade workflow area), ScreenerAgent (deterministic stock/options pipelines), ScheduledAgent (cron goals), PaymentsAgent (x402 ledger + budget guards), ReportAssetAgent, BrowserAgent/SlackAgent (channel surfaces, AIChatAgent), OptionsScannerMCP (MCP server surface). Every role is a DO binding (`ROLE_AGENT`); A2A publishes six of them as cards (orchestrator, search, payments, tasks, memory, trading) with discovery-public/invocation-gated dispatch. Cross-cutting planes: messaging bus (queues + CloudEvents), workflows (durable sagas), D1 read projection, Analytics Engine observability stream, AI Gateway (ordered failover), telemetry/calibration store. Channels (Slack, email, voice) are adapters into the shared NLQ pipeline, not separate agents. Think's topology contribution, if restored, would be sub-agent trees (parent → `chat()` children, each with its own conversation tree/memory/tools/model) and messenger ingress points; the DO topology's contribution is the binding-level addressability (name → instance, globally unique, single-threaded per instance) that both bases share.

### 10.5 Thinkagent conformance

The regime: plan `docs/agents/cloudflare.md` §14 output = `docs/agents/think-conformance.md` (baseline main `f063104`, 2026-10-20; epic #539; remediation #540/#542/#543/#545). Verdicts at baseline: Think adoption PARTIAL, version/API PARTIAL, functional completeness UNKNOWN, security/isolation PARTIAL, reliability/recovery PARTIAL, operational readiness PARTIAL. Findings F1–F6 with status in §2.3 (F1 closed; F2 resolved by the roles decision; F3/F4/F5/F6 open as recorded — re-verify before citing as current, since #1738 superseded the Think path they measured). The roles decision's designation test (§8C/§8G): Think is a chat harness; a role gains from designation only where that ownership replaces a hand-rolled equivalent; unused framework features are NOT APPLICABLE, not gaps. Under that test, restoring Think conformance today would mean: re-designating roles (ResearchAgent Required, OrchestratorAgent re-decided), re-establishing a non-stub conformance suite (F3's fix, #542, never landed on the Think path — #1738's suite replaced the question rather than answering it), and re-closing F4's silent-bypass gap (the fallback now carries identifier warnings per the #1738-era observability work, but the Think path it warned about no longer exists). Conformance, in short, is a *regime* — plan + assessment + remediation issues — and restoring it means restoring the regime, not just the base class.

### 10.6 Think workflows

`ThinkWorkflow` (from `@cloudflare/think/workflows`) connects Think to Cloudflare Workflows when a durable job needs one model-driven reasoning step: the Workflow owns the process (durable multi-step orchestration, approval gates, long waits, retryable deterministic side effects) and `step.prompt()` produces typed structured output (Zod schema) from a Think turn. Repo status: BOTH workflow classes are still `ThinkWorkflow` by ADR 0004 W13 — #1738 did not touch them, and the `@cloudflare/think/workflows` alias stays. The trade workflow's agent type parameter is `any` (W13: it never called agent methods). Distinction that matters: the repo's WorkflowPort (#1737) is the port (parent/child fan-out, collation in `agent_shard_jobs`, stage-typed commands); ThinkWorkflow is one way to put a model step inside a workflow. A revert of the agent base would not change the workflow classes; a removal of Think entirely (including workflows) would need a replacement for `step.prompt()` — either a plain-Agent workflow step or a WorkflowPort-native reasoning step — and that replacement is separate work from the agent-base question, with its own design cycle (S6 convergence #1780 is adjacent, not identical).

### 10.7 Agent-as-a-tool

Three layers, all present, with different fates in #1738:
1. **SDK `runAgentTool` (the repo's primary dispatch, base-independent):** orchestrator → `ctx.runAgentTool(ResearchAgent, …)` (researchPublish.ts, pre- AND post-#1738; ADR 0005 D4: "an SDK method, not a Think method"). Pinned by conformance/fallback/ledger tests. Survived #1738 unchanged. This is the sense in which the repo's agents are already tools for each other.
2. **SDK sub-agents / dynamic children:** `subAgent()` / `hasSubAgent()` / `listSubAgents()` / `abortSubAgent()` / `deleteSubAgent()` delegating to dynamic child DOs (`this.dynamicAgents`), each with its own isolate + SQLite, supervised by the parent (spawn/abort/delete; parent is the only way to reach them), reachable via nested URLs. Available to both bases (SDK primitives, inherited by Think).
3. **Think `chat()` sub-agent RPC (Think-only surface):** a parent drives a child over RPC; `chat()` runs a full turn (persist user message, agentic loop, persist response) with streamed events via callback; each child gets its own conversation tree, memory, tools, and model; programmatic turns (`saveMessages`, `submitMessages`, `continueLastTurn`) and auto-continuation ride the same surface. Available pre-#1738; not the repo's primary path (runAgentTool was); unavailable in the current runner except by re-adding a Think (or equivalent) turn API.
Plus the repo's own accessor layer: `getScreenerAgent`/`getResearchAgent` (orchestrator-owned DO-stub accessors used across routes; dedup belongs to S5, not to #1738). Plus the governance layer: #1744 gates agent-turn tool calls (McpAgentToolAdapter) at the same choke points as every other tool call — agent-as-a-tool is permissioned, not ambient.

### 10.8 A2A support

Present and binding-level (therefore base-independent): `src/a2a/` publishes agent cards (orchestrator, search, payments, tasks, memory, trading) with standard discovery paths (`/.well-known/agent-card.json`, `/.well-known/agent.json`, per-agent `/a2a/<agent>/agent-card.json`) and POST dispatch (`/a2a/<agent>`) via JSON-RPC through the DO stub, gated by a bearer token (`A2A_API_TOKEN`) compared timing-safely, failing closed (503 if unset — dispatch disabled rather than unauthenticated; 401 on wrong token; the gate sits ahead of agent resolution so unauthenticated callers learn nothing about which agents exist). Discovery is public; invocation is the open problem: `docs/architecture/security/mcp-security.md` §4 states invocation security "must not be claimed beyond discovery is public, invocation auth is unverified" (F-25: A2A POST per-agent authentication delegates to a DO stub and is "not verified from the entrypoint"); the secrets inventory states the concentration risk (one shared key, no per-agent tokens — a leak compromises every A2A caller at once); #1763 (CISO lane, OPEN) covers invocation-auth verification, scanner attribution, prompt-gate wiring, and A2A-wide tokens. #1738 did not change A2A: same bindings, same dispatch, actors now behind the cards instead of Think classes. A revert would not change A2A either — which is precisely why A2A must not be cited for or against either base.

### 10.9 Current RSI readiness

RSI here means the repo's recursive-self-improvement loop (NOT the Relative Strength Index indicator — no indicator was built in #1888 or anywhere in this program). Readiness today (taxonomy Level 3, not Level 4):
- **Measure:** realizations in `agent_thesis_realizations` (predicted vs realized direction, directionCorrect, falsified, optional pnlEstimatePerUnit + rMultiple), sliced by thesis/agent/structure/regime/month; per-breaker snapshots; gateway counts; retrieval counts; enrichment quality feeding the telemetry summary (#1888); observability stream (Analytics Engine, tenant-indexed) carrying counts + ids.
- **Report:** `GET /api/telemetry/summary` (realization totals, five metric slices, active calibrations, breaker health, retrieval stats, gateway stats when wired), decisions routes, chains/jobs/audit/reports surfaces, ScreenersHub Enrichment panel, last-runs UX.
- **Calibrate (governed):** falsification-gated engine (#1742: ≥20 samples + falsificationRate > 0.5 strict, thesis slices only, frozen snapshots, human non-proposer approval, applier ≠ approver) → note appended via `resolveCalibratedPrompt`; engine never rewrites prompts itself; supersede/expire reverses; enrichment calibration propose-only (409 while stopped), application is a human flag flip; #754 strategy-weight loop adjusts weights within budgets, halted outright by the adaptation kill switch.
- **Not ready / not built:** champion/challenger gate itself (#1742 is its telemetry core; §13.1 Phase 4 is the horizon); auto-tuning of thresholds; live-production verification of the `evaluateRun` hook (wiring-only claim); scheduled-screen cutover for enrichment; durable cross-instance dedup for retrieval events. Level 4 (closed-loop weight optimization, dynamic prompt optimization, champion-challenger promotion, self-healing patching) needs the Level 3 → 4 preconditions (durable actor state: DO SQLite prompt registries, sandbox shadow runs) — the actor port supplies the state shape; the loop's autonomy is intentionally capped at propose-only.
- **Think's bearing on RSI readiness:** Think's durable turns + durable submissions would make the loop's execution more interruption-proof, and Agent Skills would give the loop an on-demand capability catalog — but neither changes the governance cap (human approve/apply), which is a policy choice, not a framework limit. The DO pattern's bearing: the beforeTurn calibration plug + telemetry projection are the loop's actual hooks, and they live on the actor runner today.

### 10.10 Goal-orientation

Goals compile into chains of existing capabilities (capability composition #1362, closed): a NASDAQ100 screen sent to Slack = feed → generate → store → serve → deliver; yesterday's report by email = serve + deliver only. Chains are governed, not just executed: `chainGovernance` + `promoteChainVersion` consume chain-native authority (ADR 0014, superseding #1468 decision 1 for chains only: registry verification + Phase 3 approval for the chain's content, ordered capability-list equality) + unchanged staged rollout (shadow = held-out evidence → partial → full → completed, auto-rollback on failure signals). `chain.run` execution binding is a follow-up (MCP `chain.run` reports unimplemented — no DO/SQL runtime in MCP context; server-route binding pending). Job synthesis (#1446) composes chains from goals; the stage model (Feed and Gather separate; Analysis only on post-gather data; each stage stores its own versioned results addressable by job + stage; resumable/retryable; trigger-agnostic; sharded with timeouts → qualified partials) is the execution shape goals compile into. Goal-orientation is base-independent: chains address capabilities, not base classes — but the actor port is the surface chains' agents run on today, so a revert would re-express the chain-execution surface, not the goal model.

### 10.11 Agentic loop (Think turn lifecycle vs actor turn runner)

**Think turn lifecycle** (Think 0.19.0 `lifecycle-hooks.md`; hooks fire on every turn regardless of entry path — WS chat, sub-agent `chat()`, `saveMessages()`, durable `submitMessages()` execution, `continueLastTurn()`, auto-continuation after tool results):
`configureSession()` (once, `onStart`) → `configureContext()` (once, `onStart`) → `beforeTurn()` (inspect assembled context, override model/tools/prompt) → `streamText` loop [`beforeStep()` → `onChunk()`… → `beforeToolCall()` (ToolCallDecision) → tool executes → `afterToolCall()` → `onStepFinish()` → repeat] → `onChatResponse()` (message persisted, turn lock released) / `onChatError()` (error to propagate; `classifyChatError()` when reactive context-overflow handling is enabled). The whole turn is wrapped in a recoverable fiber (`chatRecovery`/`onExhausted` bound); session assembly merges `configureContext()` blocks; streaming is first-class (`onChunk`, stream resumption, WS protocol).
**Actor turn runner** (`actorTurnRunner.ts`):
Input normalize → delta upsert into session (upsert-by-id) → `beforeTurn()` (skipped on `configOverride`) → ONE `generateText` turn (hook's model/system prompt/tools; bound as `stopWhen: stepCountIs(maxSteps)`; `activeTools` by filtering, empty = no tools; model messages text-only; tool parts in transcript at full fidelity, not replayed) → unless abort gate fires, append assistant message + `onChatResponse()` (audit record, judge evaluation, VectorMemory remember) → on failure `onChatError()` + rethrow. No fibers, no per-step/per-tool-call/per-chunk hooks, no error classification, no context-block merging, no streaming (HTTP path returns final text), `pendingTurn` in-memory.
**Comparison in one line:** Think's loop is a durable, observable, stream-first chat machine with twelve hook points; the runner is a minimal, owned, request-scoped turn with four. The runner's minimalism is the point (ownership + testability) and also the cost (everything Think's loop did for free must be re-derived per need — D1, D2, hook granularity, submissions, sessions).
